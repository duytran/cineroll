# Changelog

All notable changes to Cineroll are recorded in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- 2026-11-24: Moved the [shoot-one-Roll plan](docs/plans/2026-11-24-shoot-one-roll.md) and the [Android setup guide](docs/android-setup.md) from older build versions to current stable ones. Before: Android Gradle Plugin 8.7.3, Kotlin 2.0.21, Gradle 8.9, API 35, CameraX 1.4.1, Compose BOM 2024.10.01. Now: Android Gradle Plugin 9.5.0 with built-in Kotlin, Kotlin 2.4.21, Gradle 9.6.0, API 37, CameraX 1.7.0, Compose BOM 2026.11.01. Why: the installed Android Studio and SDK are newer, and the project's author runs the latest Android. Some points are not verified until Task 1 builds; see the plan's `Revisions`. No ADR changes: [ADR 0005](docs/adr/0005-native-android.md) names no versions.

### Fixed

- 2026-11-24: Text on the Roll finished screen, the Film picker and the camera permission screen was black on a dark grey background, hard to read on a Pixel 9 Pro. Before: Compose's default light colours drew on the dark window theme from the manifest, and those screens set no background. Now: the app always uses Material's dark colours on a `Surface` (see [ADR 0009](docs/adr/0009-ui-is-always-dark.md)), which also makes the status bar readable over the viewfinder. The Roll finished screen has looked like this since the first slice; the picker copied it in [Task 3 of the choose-your-Film plan](docs/plans/2026-11-24-choose-your-film.md). Checked on the emulator (API 37, system in light mode): picker, viewfinder, Rewind dialog and Roll finished screen are readable. Not checked: the camera permission screen, the phone's dark mode, or a screenshot-level test.
- 2026-11-24: Saved Exposures had no date taken, because the developed JPEG carries no EXIF and Android's media provider takes the date from it when a file is published. `MediaStoreGallery` now writes the EXIF date taken (UTC, with an explicit offset) into the file before publishing it, so galleries can sort and group Exposures by date. Found on a real Pixel 9 Pro; the new `MediaStoreGalleryTest` case failed before the fix (date was `null`). The older test now checks that the stored file is still a readable JPEG of the same size, since the bytes now include EXIF. Setting only the `DATE_TAKEN` column, before or after publishing, did not stick. See [plan](docs/plans/2026-11-24-shoot-one-roll.md) Task 5.
- 2026-11-24: Exposures are now saved to `DCIM/Cineroll` instead of `Pictures/Cineroll`. Before: `Pictures/Cineroll`; the photos were saved and indexed correctly, but Google Photos showed them only under Library, Device folders, and not on the front of Library. Why: `DCIM` is the standard folder for camera photos, and a Pixel with Google Photos showed new photos from it. Photos saved earlier stay in `Pictures/Cineroll`. See [ADR 0007](docs/adr/0007-save-exposures-to-dcim.md), [plan](docs/plans/2026-11-24-shoot-one-roll.md) `Revisions`.
